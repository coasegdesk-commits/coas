# 1단계 — Replit에 입력할 내보내기 프롬프트

아래 구분선 안의 내용을 Replit Agent에 입력하세요. 이미 전달 ZIP을 받은 경우에는 나중에 최신본이 필요할 때 사용합니다.

---

현재 코아스(COAS) 인테리어하드웨어 프로젝트를 Antigravity에서 이어서 개발하기 위해 안전한 전달 ZIP을 만들어 주세요. 사이트를 새로 만들거나 현재 서비스 코드를 수정하는 요청이 아닙니다.

1. 현재 파일 구조, 실행 명령, 패키지 잠금파일, 실제 이미지 참조와 DB·외부 API 의존성을 확인하세요.
2. 현재 변경사항을 보존하세요. Git reset, checkout, clean, 강제 pull, 파일 삭제를 하지 마세요.
3. 출력은 generated-artifacts/ 아래에 만들고, 대용량 결과가 Git과 배포에 포함되지 않도록 제외 설정을 먼저 준비하세요.
4. client/, server/, shared/, script/와 실행·빌드에 필요한 루트 설정 파일을 명시적 허용목록으로 선정하세요. package.json과 package-lock.json을 함께 포함하세요.
5. client/public/ 정적 파일과 코드에서 실제로 참조하는 attached_assets/ 파일을 정확한 경로로 포함하세요. @assets 별칭 외에도 CSS url, 상대 경로, 공개 경로 참조를 조사하세요.
6. 이미지의 파일명, 한글, 공백, 괄호, 대소문자, 확장자, 파일 바이트를 유지하세요. 비슷한 이름을 같은 파일로 간주하거나 임의로 이미지를 교체하지 마세요.
7. 직접 참조 이미지와 사용 위치 목록을 만들고, 존재하지 않는 파일과 동적으로만 결정되는 경로는 따로 보고하세요. DB에만 있는 이미지와 외부 URL 이미지는 포함 여부를 명확히 구분하세요.
8. 실제 비밀값·.env·인증서·DB 덤프·고객 데이터·node_modules/·dist/·.git/·캐시·로그·내부 에이전트 자료는 제외하세요. 환경변수는 코드에서 이름과 용도만 조사하고, 비밀값을 조회하거나 출력하지 마세요.
9. 값이 비어 있는 .env.example을 전달본에만 추가하세요. 실제 프로젝트의 비밀정보 설정을 수정하지 마세요.
10. 전달할 파일을 별도 스냅샷 폴더에 복사하고, 복사 전후 SHA-256을 비교하세요. 작업 도중 원본이 바뀌면 불일치를 보고하고 다시 생성하세요.
11. 파일 경로·바이트 수·SHA-256이 포함된 FILE_MANIFEST.csv와 검증 스크립트를 넣으세요. 검증 목록에서 자기 자신의 해시는 제외한다는 점을 설명하세요.
12. ZIP 안에는 project/와 단계별 안내 문서를 두세요. 경로 이동 공격을 일으키는 ../ 경로나 심볼릭 링크는 넣지 마세요.
13. 테스트는 타입 검사·프로덕션 빌드·기존 안전한 로컬 테스트 범위에서 수행하세요. DB 변경·시딩·외부 API 호출은 하지 마세요. 기존 오류는 숨기지 말고 기록하세요.
14. ZIP CRC 검사, 파일 목록과 SHA-256 비교, 예상하지 않은 파일 누락 여부를 검증하세요.
15. 어떤 파일을 왜 넣고 뺐는지, 어떤 압축 도구와 방식을 썼는지, 실제 바이트 수와 파일 수, 검증 결과, 별도로 옮길 데이터와 설정을 설명하세요.
16. 완성한 ZIP을 다운로드할 수 있는 파일로 제공하세요. 프롬프트 문서와 실제 소스 전달본이 포함되어 있는지 명확히 알려 주세요.

중요: 원본 코드를 그대로 보존하는 전달 작업입니다. 설치·실행 오류를 발견해도 임의 리팩터링이나 라이브러리 일괄 업그레이드를 하지 말고 별도 항목으로 보고하세요.
